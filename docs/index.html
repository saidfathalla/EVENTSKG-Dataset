What's New in Release 3.0

  • Extended coverage. The editions held from 2019 to 2026 were added, including the announced editions of 2026, and missing historical editions were filled in: 2,531 editions instead of 1,951 in release 2.0 (+30%).
  • Corrected and completed data. More than 2,500 documented corrections fix wrong series, titles, places and dates inherited from earlier releases. Titles are now complete for all events and publishers for 99.5% of them.
  • Attendance mode and status. Events record whether they were held online, in person or in a mixed format, and whether they were canceled or postponed, so the move to virtual events during the COVID-19 pandemic is visible in the data.
  • Reproducible generation. The knowledge graph is regenerated from a curated CSV record by a declarative SSSOM mapping, with constraint checks and SHACL validation. Anyone can rebuild and verify the release from the published record and mapping.
  • Enrichment and interoperability. An enrichment step checks every place link against DBpedia (redirects, language chapters, kind of place), types and labels almost every resource, and links the places to Wikidata.
  • Self-describing dataset. Each edition contains a machine-readable dataset description with VoID statistics, version information and a provenance link to the previous release.
  • Backward compatible. The properties of release 2.0 and the IRIs of its events and series are kept, except three records of editions that never took place.
  • FAIR. An automated assessment with F-UJI gives the dataset a score of 100% (details).

Reproduce the Release

Every release is generated from the curated record; nothing is edited by hand in the RDF. With Python 3 and the files of the repository, a few commands rebuild and check both editions (39,480 and 44,192 triples):

git clone https://github.com/saidfathalla/EVENTSKG-Dataset.git && cd EVENTSKG-Dataset
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt

# 1. Generate: CSV + SSSOM mapping -> generated edition, VoID description, statistics
python3 scripts/csv2rdf.py data/EVENTSKG_data.csv data/eventskg.sssom.tsv --places data/dbpedia_places.csv \
        --include data/eventskg-metadata.ttl -o EVENTSKG --void VoID --stats stats/stats.html
python3 -m pyshacl -s shapes/shapes.ttl -df turtle EVENTSKG.ttl

# 2. Enrich: check places against DBpedia, add types, labels and Wikidata links
python3 scripts/enrich.py EVENTSKG.ttl -c scripts/enrich.yml -o EVENTSKG-enriched --stats stats/stats-enriched.html

# 3. Move the other formats and check everything
mv -f EVENTSKG.{nt,jsonld,rdf,n3} EVENTSKG-enriched.{nt,jsonld,rdf,n3} VoID.{nt,jsonld,rdf,n3} serializations/
python3 scripts/validate_rdf.py

Generation rejects any value that breaks a rule of the mapping (required and unique values, ISO dates, start before end, accepted ≤ submitted papers, acceptance rates in [0,1], controlled values) and reports it with its line in the record. Enrichment caches the answers of DBpedia and Wikidata (.enrich_cache.json in the repository), so it can be repeated offline with identical results. The same converter and mapping format work for any tabular data.

Interoperability

  • Standard vocabularies. Events are described with SEO and the Conference Ontology; attendance mode and status use schema.org; places use the DBpedia ontology.
  • Linked places. Every city, state or region and country is a DBpedia resource, and in the enriched edition also owl:sameAs its Wikidata item, chosen by the exact Wikipedia article.
  • Self-describing. In the enriched edition almost every resource has a type and a label, so generic Linked Data browsers and tools show names instead of bare IRIs.
  • Machine-readable mapping. The SSSOM mapping set states, field by field, which property of which vocabulary each column becomes.
  • Dataset metadata. VoID statistics, DCMI Terms metadata, version, license and a prov:wasRevisionOf link to the previous release are part of each edition.

Use Cases

  • Scientometric analysis. Growth of submissions and acceptance rates per community over five decades, the geography of events, and the shift to online events in 2020–2021.
  • Venue selection. Authors can compare venues by selectivity, community and location; steering committees can follow the progression of their series; publishers can see how their proceedings evolve.
  • Integration with scholarly knowledge graphs. Through DBpedia and Wikidata links and shared acronyms and years, EVENTSKG can be aligned with the Open Research Knowledge Graph, Wikidata, DBLP and OpenAlex.
  • Benchmarking. Small, documented and validated, the dataset suits knowledge-graph question answering and the grounding of language models in verifiable venue facts.
