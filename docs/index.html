What's New in Release 3.0

  • Extended coverage. 561 editions held from 2019 to 2026 were added, including the announced editions of 2026, and 44 missing historical editions were filled in: 2,531 events instead of 1,929 (+31%).
  • Corrected and completed data. More than 2,500 documented corrections fix wrong series, titles, places and dates inherited from earlier releases. Titles are now complete for all events and publishers for 99.5% of them.
  • Attendance mode and status. Events record whether they were held online, in person or in a mixed format, and whether they were cancelled or postponed, so the move to virtual events during the COVID-19 pandemic is visible in the data.
  • Reproducible generation. The knowledge graph is regenerated from a curated CSV record by a declarative SSSOM mapping, with constraint checks and SHACL validation. Anyone can rebuild and verify the release from the published record and mapping.
  • Enrichment and interoperability. An enrichment step checks every place link against DBpedia (redirects, language chapters, kind of place), types and labels every resource, and links all places to Wikidata.
  • Self-describing dataset. Each edition contains a machine-readable dataset description with VoID statistics, version information and a provenance link to release 2.0.
  • Fully compatible. All IRIs and properties of release 2.0 are preserved.

Reproduce the Release

Every release is generated from the curated record; nothing is edited by hand in the RDF. With Python 3 and the files of the repository, two commands rebuild both editions:

# 1. Generate: CSV + SSSOM mapping -> knowledge graph (all serialisations), VoID description, statistics
pip install -r requirements.txt
python3 csv2rdf.py data/EVENTSKG_data.csv eventskg.sssom.tsv --places data/dbpedia_places.csv \
        -o release/EVENTSKG --void release/VoID --stats release/stats.html
python3 -m pyshacl -s shapes.ttl -df turtle release/EVENTSKG.ttl

# 2. Enrich: check places against DBpedia, add types, labels and Wikidata links
python3 enrich.py release/EVENTSKG.ttl -o release/EVENTSKG-enriched --stats release/stats-enriched.html

Generation rejects any value that breaks a rule of the mapping (required and unique values, ISO dates, start before end, accepted ≤ submitted papers, acceptance rates in [0,1], controlled values) and reports it with its line in the record. Enrichment caches the answers of DBpedia and Wikidata, so it can be repeated offline with identical results. The same converter and mapping format work for any tabular data.

Interoperability

  • Standard vocabularies. Events are described with SEO and the Conference Ontology; attendance mode and status use schema.org; places use the DBpedia ontology.
  • Linked places. Every city, state or region and country is a DBpedia resource, and in the enriched edition also owl:sameAs its Wikidata item, chosen by the exact Wikipedia article.
  • Self-describing. In the enriched edition almost every resource has a type and a label, so generic Linked Data browsers and tools show names instead of bare IRIs.
  • Machine-readable mapping. The SSSOM mapping set states, field by field, which property of which vocabulary each column becomes.
  • Dataset metadata. VoID statistics, DCMI Terms metadata, version, licence and a prov:wasRevisionOf link to the previous release are part of each edition.

Use Cases

  • Scientometric analysis. Growth of submissions and acceptance rates per community over five decades, the geography of events, and the shift to online events in 2020–2021.
  • Venue selection. Authors can compare venues by selectivity, community and location; steering committees can follow the progression of their series; publishers can see how their proceedings evolve.
  • Integration with scholarly knowledge graphs. Through DBpedia and Wikidata links and shared acronyms and years, EVENTSKG can be aligned with the Open Research Knowledge Graph, Wikidata, DBLP and OpenAlex.
  • Benchmarking. Small, documented and validated, the dataset suits knowledge-graph question answering and the grounding of language models in verifiable venue facts.
